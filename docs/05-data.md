# 05. 데이터 계획

## 1. 결정 사항

### 1.1 수집 방법: 합성 천장뷰 생성기 (`sim/`)

실제 촬영은 하지 않는다. 데이터는 모두 Python(numpy + OpenCV)으로 그린 96×72 그레이스케일 프레임이고, **정답은 생성 과정에서 자동으로 나온다.**

**카메라 모델** (`03-hardware.md`와 일치)

| 항목 | 값 |
|---|---|
| 천장 높이 | 2.7m |
| 화각 | 가로 54°, 세로 41° |
| 프레임 속도 | 8 FPS |
| 원근 효과 | 투영 배율 = f / (천장 높이 − 대상 높이). 키가 큰 사람은 더 크게, 더 빨리 지나가는 것처럼 보인다 |

**사람 모델** (위에서 본 모습)

| 요소 | 분포 | 비고 |
|---|---|---|
| 키 | 1.50~1.90m (균등) | 아이(1.0~1.3m)는 어려운 케이스로 별도 소량 |
| 어깨 | 타원, 폭 0.40~0.50m × 두께 0.22~0.28m | 옷 밝기 무작위 |
| 머리 | 타원, 0.15~0.20m × 0.18~0.22m | 머리카락 밝기: 어두움 70%, 밝음·모자 30% |
| 몸 방향 | 진행 방향 ± 15° | |
| 소지품 (방해 요소) | 백팩·가방 타원 20% | 머리로 착각하면 안 되는 블롭 |

**궤적**

| 항목 | 분포 |
|---|---|
| 속도 | 0.8~1.6m/s |
| 좌우 흔들림 | ±5cm 사인파 |
| 진입 위치 | 문 폭 전체에 고르게 |
| 비통과 동작 | 멈칫, 되돌아감(U턴), 문 앞 서성임 |

**화면 변이**

- 바닥 질감 4종 (타일, 노이즈, 단색, 그라데이션)
- 밝기와 감마 무작위
- 센서 노이즈 (σ = 2~8)
- 통행 방향 모션 블러 (속도에 비례)
- 비네팅

### 1.2 시나리오 구성

| 범주 | 내용 | 테스트 세트 비율 |
|---|---|---|
| `single` | 1명 IN 또는 OUT | 35% |
| `side_by_side` | 2명 나란히, 머리 중심 간격 0.20~0.50m | 15% |
| `front_back` | 2명 앞뒤, 간격 0.30~0.80m (꼬리물기 전형) | 15% |
| `opposite` | 1명 IN, 1명 OUT 동시에 교차 | 10% |
| `negative` | U턴, 서성임, 빈 화면, 가방만 지나감 | 15% |
| `group3` | 3명 연속 | 5% |
| `occluded_pair` | 머리 간격 0.18m 미만 (안고 통과 등) | 5%. **알려진 한계라 게이트에서 제외**하고 따로 보고 |

**모의 인증 타임라인**: 시나리오마다 생성한다. 인증 시각은 첫 통과 시각보다 0.5~3초 앞선다.

| 패턴 | 인증 | IN | 기대 결과 |
|---|---|---|---|
| 정상 | 1회 (허용 1) | 1명 | 알림 없음 |
| 함께 인증 | 2회 | 2명 | 알림 없음 |
| 동반입장 | 1회 | 2명 | `tailgate` |
| 미인증 입장 | 0회 | 1명 | `unauth_entry` |
| 퇴장 | 없음 | OUT만 | 알림 없음 |

### 1.3 라벨링 기준 (생성기가 자동 적용)

| 항목 | 기준 |
|---|---|
| 머리 중심 | 머리 꼭대기 중심을 영상 평면에 투영한 좌표 (x, y), 서브픽셀 |
| 가시 비율 `vis` | 머리 타원 면적 중 실제로 보이는 비율. 화면 밖으로 나간 부분과 **더 높은 표면(다른 사람의 머리·어깨)에 가려진 부분**을 뺀다 |
| 양성·무시 | `vis ≥ 0.5`면 양성. `0 < vis < 0.5`인 칸은 손실 계산에서 **무시(마스크)**. 반쯤 잘리거나 가려진 머리를 음성으로 가르치지 않기 위함 |
| 통과 이벤트 | 머리 중심이 바깥 구역(y < 24px)에서 안쪽 구역(y > 48px)까지 이동하면 IN, 반대면 OUT. U턴·되돌아가는 서성임은 이벤트 없음 (후처리의 라인 2개 히스테리시스와 같은 규칙) |
| 이벤트 시각 | 머리 중심이 가운데 선(y = 36px)을 마지막으로 지난 시각 (5ms 해상도로 계산) |
| 평가 매칭 | 예측 이벤트와 정답 이벤트는 **방향이 같고 시각 차이가 0.5초 이하**이면 짝지음 (1:1, 시각 차이가 작은 순) |
| 밀착 부분집합 | 범주 `side_by_side` + `front_back` (CI 게이트 기준, `09-ci.md`) |

**출력 파일**

| split | 파일 | 내용 |
|---|---|---|
| val, test | `scenarios.json` | 아래 항목의 배열 (프레임별 머리 라벨 포함) |
| val, test | `frames.npz` | 시나리오 ID별 프레임 `uint8 [n_frames, 72, 96]` |
| train | `train.npz` | 시나리오당 8프레임 샘플: `x uint8 [N, 72, 96]`, `heads float32 [N, 4, 3]` (x, y, vis, 빈 칸은 NaN) |
| train | `scenarios.json` | 프레임 라벨을 뺀 메타데이터 |

**시나리오 항목 형식** (`scenarios.json`의 원소)

```json
{
  "scenario_id": "fb_0007",
  "seed": 300007,
  "split": "test",
  "category": "front_back",
  "subtype": "front_back_in",
  "fps": 8, "width": 96, "height": 72,
  "scenario_start_ms": 1793682000000,
  "n_frames": 80,
  "idle_gap_s": 0,
  "camera": {"ceiling_m": 2.7, "hfov_deg": 54, "vfov_deg": 41},
  "texture": "planks",
  "lighting": {"gain": 1.02, "gamma": 0.97, "vignette": 0.12, "noise_sigma": 4.1, "blur_s": 0.0},
  "persons": [{"pid": 0, "kind": "person", "height_m": 1.712, "backpack": false}],
  "frames": [{"idx": 0, "heads": [{"pid": 0, "x": 51.2, "y": -3.0, "vis": 0.0}]}],
```

### 1.4 합성 데이터 활용 방식

- 학습·검증·테스트를 **모두 합성 데이터로** 한다.
- 이 방식으로 증명하는 범위:
  - 파이프라인(모델 → 후처리 → 서버 규칙)이 끝까지 동작한다.
  - 밀착 통과를 다루는 설계가 **통제된 조건에서** 효과가 있다.
- 증명하지 않는 범위: 실제 매장 정확도.
- **도메인 갭 완화** (실제 영상에 가깝게 만들어 일반화를 돕는 장치):
  - 질감·조명·노이즈·블러를 무작위로 바꾼다.
  - 테스트 세트에는 학습에 쓰지 않은 **바닥 질감 1종과 극단 조명**을 넣는다.
- **실제 데이터로 넘어갈 때 (범위 밖)**:
  - 본인 집 문 위에 보드를 달고 본인만 촬영한다.
  - 데이터는 로컬에만 보관하고 학습 후 삭제한다.
  - 소량의 실제 데이터로 미세조정한다.

### 1.5 학습·검증·테스트 분할

| 세트 | 규모 | 생성 방식 | 용도 |
|---|---|---|---|
| train | 시나리오 2,500개에서 약 2만 프레임을 뽑음. 밀착 프레임은 30% 이상이 되도록 과대 샘플링 | 시드 100000번대, 바닥 질감 A~D | 학습 |
| val | 시나리오 200개 | 시드 200000번대, 질감 A~D | 임계값·후처리 파라미터 조정, 조기 종료 |
| test | 시나리오 300개 | 시드 300000번대, **절반은 처음 보는 질감 E(planks)**, 극단 조명 20% | CI 게이트 (한 번 정하면 고정) |
| device | test 중 9개 (범주별 1~2개, 장시간 체류 시나리오 포함) | test에서 선택 | 기기 Flash에 넣어 PC 결과와 같은지 확인 |

- **분할 단위**: 시나리오 단위로 나눈다. 프레임 단위로 나누면 연속 프레임이 학습과 테스트에 함께 들어가서 정확도가 부풀려진다.
- **저장소 관리**:
  - 데이터는 커밋하지 않는다. CI는 **고정 시드로 test 세트를 다시 생성**한다 (300개 기준 1분 미만 추정).
  - 대신 생성기 코드와 설정 파일, 그리고 test 세트 정답의 해시를 커밋한다.
  - 생성기 코드가 바뀌어 해시가 달라지면 CI가 실패한다. 게이트 기준이 몰래 바뀌는 것을 막기 위함이다.
- **모델 파일**: `model.tflite`(약 20KB)는 커밋한다. CI는 학습하지 않고 **커밋된 모델을 평가만** 한다.

### 1.6 어려운 케이스 확보 전략

1. **파라미터 격자 탐색**: 간격 {0.20, 0.25, 0.30, 0.35, 0.40, 0.50}m × 배치 {나란히, 앞뒤, 대각} × 키 차이 {0, 0.15, 0.30}m × 속도 차이 {0, 0.3}m/s를 빠짐없이 생성한다. 실패 경계가 어디인지 표로 보여 줄 수 있다.
2. **어려운 샘플 재학습**(1회): 1차 학습 후 시나리오 2,000개를 새로 생성해서 평가한다. 틀린 시나리오의 파라미터 근처에서 데이터를 더 생성해 재학습한다.
3. **외형 교란**:
   - 어두운 바닥 위의 검은 머리 (저대비)
   - 흰 모자 (밝은 머리)
   - 머리 뒤의 백팩 블롭
4. **비통과 음성**: U턴, 라인 위 서성임, 반대 방향 교차는 중복 계수와 방향 오류를 확인하는 용도다.
5. **5 FPS 조건**: 테스트 프레임을 하나 건너 하나씩 써서 따로 평가한다. 저속 카메라에서 추적이 버티는지 보기 위함이다.

## 2. 결정 근거

- **자동 라벨링의 이점**: 3시간 안에 사람이 직접 라벨링하는 것은 불가능하다. 합성 데이터는 정답이 정확하고, 밀착 간격 같은 변수를 **정확히 통제**해 실험할 수 있다.
- **test 세트에 처음 보는 질감을 넣는 이유**: 학습 분포를 외운 것인지, 머리 형태를 배운 것인지를 구분하기 위함이다.
- **occluded_pair를 게이트에서 빼는 이유**: 물리적으로 분리할 수 없는 케이스다. 게이트에 넣으면 모델 개선과 무관하게 수치만 흔들린다. 숨기지 않고 따로 보고한다.
