# 10. 테스트 및 평가 계획

## 1. 결정 사항

### 1.1 평가 지표

| 영역 | 지표 | 정의 | 목표 (`01-requirements.md`) |
|---|---|---|---|
| 카운팅 | 시나리오 정확도 | 예측 (IN 수, OUT 수) = 정답인 시나리오 비율 | 단독 ≥ 0.90, 밀착 ≥ 0.70 |
| 카운팅 | 이벤트 정밀도·재현율·F1 | 방향이 같고 시각 차이 ≤ 0.5초인 1:1 매칭 | 보고만 함 |
| 카운팅 | 시나리오별 인원 오차(MAE) | 예측 인원과 정답 인원의 차이 평균 | 보고만 함 |
| 양자화 | int8 − float 정확도 차 | 같은 테스트 세트 | ≤ 2.0%p |
| 규칙 | 동반입장 재현율·정밀도 | 시나리오 단위 기대 알림 대비 | 각각 ≥ 0.80 |
| 규칙 | 알림 지연 | 세션 마지막 이벤트 → 알림 생성 (시나리오 시각) | ≤ 세션 간격 5초 + heartbeat 2초 |
| 기기 | 추론 시간 (p50 / 최대), FPS | heartbeat 로그 | ≤ 200ms, ≥ 5 FPS |
| 기기 | 아레나 사용량, `min_free_heap` 추세, 재부팅 횟수, `dropped` | heartbeat·boot 로그 | 소크 테스트에서 힙 감소 추세 없음, 재부팅 0 |
| 기기 | PC↔기기 동치성 | 같은 시나리오의 이벤트 순서·방향·프레임 번호 | 9개 시나리오 100% 일치 |
| 종단 | 이벤트 → DB 지연 | `received_ms − 전송 시각` | ≤ 2초 |
| 개인정보 | 이미지 저장 0, 정의되지 않은 필드 거부 | 서버 테스트 | 실패 0 |

### 1.3 비교 실험

| ID | 실험 | 방법 | 보여 주려는 것 | 우선순위 |
|---|---|---|---|---|
| E1 | **양자화** float vs int8 | CI 게이트 결과 그대로 사용 | 온디바이스용 int8 변환의 손실 | 반드시 (CI가 자동 산출) |
| E2 | **장기 체류 정의 비교**: 확정값 vs 이전 정의("매장이 T분 동안 비지 않음") | 저통행·붐빔·회전형(장기 체류자 없음) 이벤트 스트림 30개에 두 정의를 적용 | 확정값은 오탐 0, 대신 붐빌 때 지연. 이전 정의는 회전형에서 오탐 | 반드시 (Python·SQL만, 약 10분) |
| E3 | **후처리 구성 요소 제거 실험** (ablation) | 밀착 부분집합에서 ① 임계값 블롭 vs 지역 최대값 ② 등속 예측 유무 ③ 라인 1개 vs 2개 히스테리시스 | 설계 선택마다 밀착 정확도에 기여하는 정도 | 시간이 되면 |
| E4 | **단순 센서 방식 vs 모델 방식** | 같은 정답 궤적으로 IR 빔 2개를 시뮬레이션. 몸 타원이 빔 선과 겹치면 차단으로 보고, 차단 순서로 방향 판정 | 앞뒤 밀착에서 빔이 두 사람을 하나로 합치는 문제 vs 모델의 분리 능력 | 시간이 되면 (O5) |
| E5 | 8 FPS vs 5 FPS | 테스트 프레임을 하나씩 건너뜀 | 저속 카메라에서 추적이 버티는지 | 시간이 되면 |

**E4 결과 해석 시 주의**: 빔 시뮬레이션은 "몸이 선을 가리면 차단"이라는 이상화된 모델이다. 실제 IR 빔에는 노이즈와 반사가 있다. 이 실험의 결론은 "**같은 정답 궤적에서 정보량이 다르다**"는 것에 한정한다.

### 1.4 결과 기록

- **CI 결과**: 잡 요약과 아티팩트(`report/*.json`)
- **기기 결과**: DB `device_logs`에서 07 문서 4.6절 쿼리로 뽑아 표로 정리
- **최종 표**: `docs/results.md`(데모 후 작성)에 성공 기준별로 목표, 측정값, 통과 여부를 기록한다. 미달 항목은 원인과 함께 그대로 적는다.

## 2. 결정 근거

- **시나리오 완전 일치를 게이트로 쓰는 이유**: 이벤트 F1은 "1명 더 셈"과 "방향 틀림"이 서로 상쇄돼 보일 수 있다. 출입 대조에 필요한 것은 시나리오 단위의 **정확한 인원**이다.
- **E2를 반드시로 둔 이유**: 비용이 거의 없다. 그리고 "왜 확정값인가"라는 설계 결정을 수치로 뒷받침한다.
- **TC-12처럼 한계를 테스트로 고정하는 이유**: 알려진 한계의 동작이 나중에 몰래 바뀌는 것을 막는다.

## 3. 대안과 트레이드오프

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 실제 사람을 촬영해 평가 | 현실 성능 | 시간, 개인정보 동의 | 범위 밖 |
| 프레임 단위 검출 mAP | 모델 비교에 표준 | 최종 목적(인원·방향)과 거리가 멂 | 보조 지표로도 쓰지 않음 |
| E4를 실물 IR 센서로 | 실측 | 예산 0원 | 시뮬레이션으로 대체 |
