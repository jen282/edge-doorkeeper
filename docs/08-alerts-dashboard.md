# 08. 알림 및 대시보드

## 1. 결정 사항

### 1.1 알림 조건

| 종류 | 조건 | 심각도 | 판정 시점 |
|---|---|---|---|
| `tailgate` (동반입장 의심) | 출입 세션의 IN 수 > 허용 인원 합 (허용 ≥ 1) | warn | heartbeat (세션이 닫힌 뒤) |
| `unauth_entry` (미인증 입장) | 출입 세션에 인증 없이 IN 발생 | warn | heartbeat |
| `long_stay` (장기 체류) | 장기 체류 확정 인원 ≥ 1 (`07-database.md` 4.2절) | warn | heartbeat |
| `night_stay` (심야 체류) | 현지 00:00~05:00에 매장 내 인원 > 0 | info | heartbeat |
| `device_offline` (감시 공백) | heartbeat가 10초 이상 수신되지 않음 | crit | 서버 감시 태스크 (5초 주기, 벽시계) |
| `count_anomaly` (카운트 오차) | 매장 내 인원 < 0 | info | heartbeat |

**설정값**

| 키 | 기본값 | 바꾸는 곳 |
|---|---|---|
| `t_long_ms` (장기 체류 기준) | 30분 | **대시보드 드롭다운** → `settings` 테이블 |
| `SESSION_GAP_MS` | 5000 | 서버 환경변수 |
| `NIGHT_WINDOW` | 00:00~05:00 Asia/Seoul | 서버 환경변수 (심야 시나리오는 01:00 KST로 생성) |
| `OFFLINE_MS` | 10000 | 서버 환경변수 |

### 1.2 알림 표시: 대시보드 전용

- **외부 채널 없음**: Discord, 이메일 같은 외부 알림은 쓰지 않는다. `alerts` 테이블이 원본이고, **대시보드가 1초마다 조회**해서 표시한다.
- **새 알림 표시**:
  - 우측 알림 목록 맨 위에 강조(배경색)해서 추가한다.
  - `warn` 이상이면 상단 배너를 3초 동안 띄운다.
  - 소리 알림은 넣지 않는다 (시간이 되면).
- **확인 처리**: [확인] 버튼을 누르면 `acked=1`이 되고 강조가 해제된다. 확인되지 않은 알림 수는 상단에 배지로 표시한다.
- **문구 원칙**:
  - 사람이 아니라 **상황과 시각**을 쓴다.
  - 단정하지 않고 "의심"으로 쓴다.

```
동반입장 의심 · 14:02:11~14:02:15 · 인증 1 / 입장 2
장기 체류 1명 · 13:05:12~13:31:40 사이 입장 · 30분 기준
```

서버 콘솔에도 같은 내용을 구조화 로그로 남긴다 (디버깅용).

### 1.3 대시보드 화면 구성 (반드시 구현)

```
┌─────────────────────────────────────────────────────────────────────────┐
│ edge-doorkeeper  기준 시각 14:02:11 (재생 모드)  기기 ● 정상 41ms·8fps  미확인 2 │
├───────────────────────────────────┬─────────────────────────────────────┤
│                                   │  현재 매장 인원            2명        │
│   실시간 뷰 (ESP32 직결)            │  오늘 누적 입장            42명       │
│   ┌──────┐                        │  장기 체류 인원            1명        │
│   │ #3 IN│  ← 파랑 박스            │  장기 체류 기준   [ 30분       ▼ ]    │
│   └──────┘                        ├─────────────────────────────────────┤
│   ─ ─ ─ 라인 A ─ ─ ─               │  알림                                │
│        ┌────┐                     │ ■ 14:02:11 동반입장 의심 인증1·입장2 [확인]│
│        │ #4 │ ← 초록 박스           │   13:31:40 장기 체류 (30분 기준)   [확인]│
│        └────┘                     │   01:12:40 심야 체류               [확인]│
│   ─ ─ ─ 라인 C ─ ─ ─               │                                     │
└───────────────────────────────────┴─────────────────────────────────────┘
```

| 영역 | 내용 | 데이터 출처 | 갱신 |
|---|---|---|---|
| 상단 바 | 기준 시각(heartbeat 시각, 재생 모드면 표시), 기기 상태, 추론 시간·FPS, 미확인 알림 수 | `/v1/occupancy` | 1초 |
| 좌측 실시간 뷰 | `<img src="{stream_url}?token=...">`, 5배 확대 (`image-rendering: pixelated`) | ESP32 `:81/stream` | MJPEG 연속 |
| 우측 상단 집계 | 현재 매장 인원, 오늘 누적 입장, **장기 체류 인원(확정값 1개)** | `/v1/occupancy` | 1초 |
| 장기 체류 기준 드롭다운 | 10초·30초 (데모), 5분, 10분, 30분, 1시간 | `GET/PUT /v1/settings` | 변경 즉시 |
| 우측 하단 알림 | 최신 20건, 미확인 강조, [확인] 버튼 | `/v1/alerts`, `POST /v1/alerts/{id}/ack` | 1초 |

**실시간 뷰 대체 표시**: 스트림 연결에 실패하면(기기 오프라인, 토큰 오류, 다른 사람이 시청 중) 좌측에 "영상 연결 안 됨 (사유)"를 표시한다. 우측 집계는 그대로 동작한다.

**드롭다운 동작 순서**

1. 사용자가 값을 선택한다.
2. `PUT /v1/settings/t_long_ms`로 저장한다.
3. 서버가 즉시 규칙을 재평가하고(`now` = 마지막 heartbeat 시각), `settings_log`에 기록한다.
4. 다음 1초 폴링에서 장기 체류 인원과 알림이 새 기준으로 갱신된다.

**구현 방식**

- FastAPI가 `server/static/index.html` + `app.js`를 제공한다.
- 바닐라 JS로 `fetch`를 호출하고, 프레임워크나 빌드 도구는 쓰지 않는다.
- 차트 라이브러리도 쓰지 않는다 (시간대별 차트는 선택 항목이다).

### 1.4 시간이 되면 추가

- 하단 시간대별 입장·퇴장 막대 차트 (`/v1/stats/hourly`, Chart.js CDN)
- CCTV 태그 검색 (종류, 기간 → 시각 목록, [시각 복사] 버튼)
- 기기 건강 추세 (`min_free_heap`, 추론 ms). 소크 테스트에서 메모리 누수가 없다는 증거 화면으로 쓴다

## 2. 결정 근거

- **외부 채널을 빼고 대시보드에만 표시하는 이유**: 데모 환경에서 외부 채널은 설정 비용만 들고 검증 가치가 작다. DB가 원본이므로 나중에 외부 채널을 붙여도 구조는 바뀌지 않는다.
- **드롭다운 설정을 DB에 저장하는 이유**: 화면 숫자와 알림 판정이 **같은 값**을 쓰게 하고, 서버가 재시작돼도 유지되게 하려는 것이다. 변경 이력이 있으면 "왜 이때 알림이 났나"를 설명할 수 있다.
- **장기 체류 인원을 확정값 하나로 표시하는 이유**: 비식별 원칙 아래에서 거짓 없이 말할 수 있는 숫자이고, 알림 조건과도 같은 숫자다.
- **1초 폴링을 쓰는 이유**: 서버 푸시(SSE·WebSocket)보다 코드가 짧고, LAN·단일 사용자 환경에서는 부하가 문제되지 않는다.

## 3. 대안과 트레이드오프

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| SSE로 알림 푸시 | 즉시성, 요청 수 감소 | 연결 관리 코드 추가 | 사용자가 늘면 전환 |
| 영상을 서버가 중계 (서버가 ESP32 스트림을 받아 다시 전송) | 브라우저가 기기 IP를 몰라도 됨, 접근 제어를 서버로 일원화 | 영상이 서버를 거침 (원칙 위반) | 기각 |
| 박스를 브라우저 canvas에 그리기 (좌표는 별도 JSON) | 기기 부담 감소 | 프레임과 좌표 동기화 문제, 좌표가 기기 밖으로 나감 | 기각 |
| 장기 체류를 범위(최소~최대)로 표시 | 정보량이 많음 | 해석이 어렵다는 피드백 | 기각 (확정값 1개) |
| 장기 체류를 "가능한 최대 인원"으로 표시 | 놓치지 않음 | 붐비는 시간대에 오탐이 계속 남 | 기각 |
| 외형 재식별로 정확한 체류 시간 계산 | 붐빌 때 지연이 줄어듦 | 매칭 오류 시 오탐, 생체인식정보 해당 가능성 | 기각 (개인 식별·재식별 안 함, `02-architecture.md` 1.6절) |
| 입·퇴장 인증 세션 토큰 | 식별 없이 정확 | 퇴장 인증이라는 운영 변경 필요 | 실서비스 확장안으로만 기록 |
| Streamlit·Grafana | 빠른 차트 | 실시간 뷰와 드롭다운 배치가 제한적, 의존성 추가 | 기각 |
